# @deepseek-ai/dsh-client-ui-knowledge

[English](README.md) | 中文

## 概述

在对话里直接检索公司知识库。输入 `@` 会列出当前账号可见的库，选中后作为作用域 chip 插进消息，下一轮提问自带范围，不用依赖模型记住。这一轮真正检索到的每个片段变成回答下方的角标，点角标在右栏打开那段原文，可以展开全文，也可以把它带回输入框接着问。答案需要引用内部文档时选它。

<a id="what-it-registers"></a>
## 注册了什么

- **`@` 触发源。** 输入 `@` 列出当前账号可见的库，外加一行打开面板。选中库会插入一个原子引用，模型侧看到的是 `<knowledge-base>库名</knowledge-base>`。
- **引用节点。** 带这个标记的消息渲染成 chip，作用域在用户自己的消息里可见，回放时也一样。
- **出处条。** 回答结束后，这一轮真正检索到的每个片段变成一个角标。点角标用该轮的片段打开证据页，并聚焦点击的那一条。
- **证据页。** 右栏的一个页面，能浏览库和文档、自己检索、把勾选的库带回输入框（「用这 N 个库提问」），也能把某段展开成全文再作为问题发回去。
- **词条。** 把 `knowledge` 命名空间注册进 `ctx.locale`。

列表、检索和片段都来自网关：`GET /__vh/weknora/api/v1/knowledge-bases`、`POST /__vh/weknora/api/v1/knowledge-search` 与 `GET /__vh/weknora/api/v1/chunks/{id}` 带着页面自己的 cookie 会话，由网关附上用户的 VOS 令牌。浏览器和 agent 都不接触知识库凭据，每个界面看到的都正好是这个人有权读的内容。

<a id="how-citations-are-derived"></a>
## 出处是怎么来的

`weknora` skill 每次调用打印一个 JSON 对象，这里只读它打印的两种形状：`search` 的 `citations` 数组，以及 `read` 的 `chunks` 数组连同它的 `knowledge` 头。两种都没有的结果不贡献任何东西，所以无关调用无法凭空造出一个出处，同一次检索重跑也仍然是一个角标。

不从正文里推断。模型提到一个它没检索到的片段不会产生角标——出处条告诉读者的是一次运行看到了什么，而不是它说了什么。

<a id="how-it-fails"></a>
## 失败时怎么表现

网关列不出知识库时，面板的列表是空的，`@` 菜单里只剩打开面板那一行。这是有意的：这次选择仍然表示「去问知识库服务」，真正的原因（服务未启动、令牌过期、没有分配库）由 skill 如实报出，而不是让菜单去猜。

失败的列举不会被缓存，服务恢复后下一次敲键就能看到，不必刷新页面。证据页读不到库列表时在自己的状态行说明，并在此期间检索全部可见库；检索失败时用一行说明替换列表，而不是留一个空结果。

<a id="model-experience"></a>
## 模型体验

### 用户消息里的作用域标记

#### 模型看到什么

选中库的那条用户消息里的 `<knowledge-base>库名</knowledge-base>`。仅此而已：出处条、面板和展开都是客户端表面，不占提示词。

#### Token 影响

每次选择几个 token，上限就是库名的长度。片段、角标和面板状态从不进入请求。

#### KV Cache 影响

没有。标记在用户消息里而不是系统前缀里，它上方的客户端表面只在这一轮结束后才存在。

## 已知限制与待办

<a id="known-limitations-and-deferred-work"></a>

- 库列表在页面生命周期内缓存；别处新建的库需要刷新页面才出现。
- 选库只是在消息里声明范围，没有任何机制阻止模型去别处检索，这个引用仍是建议性的。
- 出处条读的是 skill 打印的内容；JSON 没有完整输出的那次运行不会产生角标。
