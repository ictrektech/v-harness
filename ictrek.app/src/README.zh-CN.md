# v-harness

升级时保留应用存储，为旧 `amd` 和 `arm` 分别选择 `amd-cpu` 和 `arm-cpu`。通过 VOS API 升级时显式传入新 `profiles`。回退时选择旧版本对应选项。应用 API 保持一致。

多用户 agent 工作台。每位用户拥有独立的会话、工作区和产物，互相不可见。

VOS 版本以前缀跟随官方 DSH 版本，后缀 `.vos.xx` 记录本项目的发布次数，例如 `0.2.2-rc.1.vos.01`。同一官方版本下递增，切换官方版本后从 `.vos.01` 重新计数。

## 使用

1. 在 VOS 中打开 v-harness，**无需注册或登录**：平台身份自动接入。
2. 在左侧会话栏新建对话，直接描述你要完成的事。
3. agent 会在你的工作区里读写文件、执行命令，产物出现在「日常」目录或你指定的项目目录。

## 目录

- `workspace/日常/`：没有指定项目时的默认落点，闲聊与临时任务都在这里。
- `workspace/<项目>/`：自建项目目录。

## 注意

- 每位用户独立进程与独立账号，任何用户都读不到其他人的会话、文件或凭据。
- 文件管理只展示你自己的 `workspace/`，隐藏文件不可下载。
- 打开「设置 → 模型」。可在新对话默认模型下拉框选择 V-Scheduler 或已保存的个人模型。V-Scheduler 模型由当前 VOS 身份访问，纯文本补全模型不支持工具调用。

### 使用自己的模型

可直接配置个人模型来运行 v-harness，V-Scheduler 为可选依赖。

v-harness 的安装清单只声明 V-Scheduler，不声明 V-Voice、Image Studio 或其他应用依赖。调用这些应用的 API 属于按需集成：未安装时仅对应功能不可用，不应阻止 v-harness 安装、升级或使用个人模型。此变更只调整安装约束，不改变功能 API 的请求和响应。

1. 打开「账号菜单 → 设置 → 模型 → 添加模型提供商」。
2. 选择「第三方模型提供商」，从目录选择提供商，填入自己的 API 密钥并保存。使用自建或兼容服务时，选择「自定义模型 API」，填写提供商标识、API 地址、协议、模型 ID 和所需密钥，再保存。服务地址需能从 v-harness 所在环境访问。
3. 在本页的「新对话默认模型」选择个人模型，或从当前会话输入框右下角的模型菜单切换。已有会话保留已选模型。列表未更新时点击「刷新模型列表」，并检查地址、协议、模型 ID 和凭据。

### 自定义 Agent Teams 的分工

在会话里指定要创建的成员、各自的职责、任务依赖，以及是否先等待确认。生成草案后，在会话标题栏或回复下方的团队卡片点「查看团队」，打开「团队协作」。草案阶段可先查看面板。启动后，在成员列表看分工，在依赖图点开任务看负责人及前置任务，在总进度看完成情况。草案阶段可调整已有成员的角色和模型，也可新增、修改或删除任务。需要新增成员或整体调整分工时，点击「返回对话修改」，在会话里说明修改要求。保存后点击「确认并启动团队」，再点击「确认启动」。团队启动后，通过对话提出新的分工调整。

> 创建一个 Agent Teams 团队。成员 A 分析需求，输出验收条件，不修改代码。成员 B 按 A 的结论实现，等 A 完成后开始。成员 C 在 B 完成后独立审查实现和测试。先列出成员、任务和依赖，只创建草案，等我确认后再启动。

在「设置 → API 文档」查看 VOS OAuth2 鉴权、创建会话、提交任务、读取结果及错误处理。

## VOS 运维

打开「账号菜单 → 设置 → VOS 运维」，由当前 VOS 系统管理员点击「授权诊断」。每次授权持续 15 分钟，退出诊断可提前结束。其他角色会收到权限提示。

- 启动失败时先查看应用的状态、最近错误和 VOS 工作流，再打开相应主栈容器最近 150 行日志。日志上限 512 KiB，日志驱动不可读或响应超过上限时会报错。
- 输入宿主机端口，查找 Docker 发布端口对应的容器和协议。宿主机进程、host 网络监听和未发布的端口不在此列表内。
- 容器清单标明对应的应用版本。只有可识别、属于仍在本机安装的应用、版本与当前安装不同且处于 created 或 exited 状态的主栈容器可清理。删除容器会移除其可写层，保留卷。管理员可在「完全访问（VOS 运维）」会话中请求清理未使用镜像，包括无标签和带标签两类。在确认框中核对完整镜像 ID 与标签后点击确认或跳过。系统在删除前重新核对引用，Docker 拒绝非强制删除时会显示冲突。未开启「完全访问（VOS 运维）」时，会话会提示管理员开启。租户终端的 Docker 清单仅覆盖当前租户。 完整用法和错误码见「设置 → API 文档」。
- 重启应用或清理对象时，核对预览中的应用 ID、容器 ID 或镜像 ID，点击「确认执行」或「跳过」。预览 60 秒内单次有效，目标发生变化时必须重新预览。重启由 VOS 执行，受理后会显示任务 ID。

VOS 系统管理员在会话里选择「完全访问（VOS 运维）」即可直接诊断。Agent 提出停止容器、重启应用或清理时，会话里会显示具体目标并请管理员确认。会话继续使用工作区沙箱。支持的操作见「设置 → API 文档」。

如果旧版 VOS 容器占用端口或持有 runner 文件锁，在会话中选择「完全访问（VOS 运维）」并让 Agent 检查应用。核对「停止旧版容器」提议，点击「确认执行」或「跳过」。刷新清单后，可再请求重启当前应用或单独清理已退出的容器。停止操作保留容器及数据。`stoppable` 表示容器可识别、处于运行或重启中，所属应用已安装或停止，容器版本与当前安装版本不同，且所属应用不是 v-harness。停止前会重新校验当前安装版本和安装 ID。目标变化或不符合条件时返回 409 `target-changed`。

查应用状态或请求重启时，请使用清单中的应用 ID。修复提议等待用户确认，返回 `executed: false`。已有提议时，HTTP 409 `confirmation-pending` 返回该提议的 `action`、`id` 和剩余秒数 `expiresIn`。请在会话里确认或取消。过期或已使用的确认返回 409 `confirmation-unavailable`。应用状态收到 Docker ID 时返回 400 `app-id-required`，请在清单里看容器状态或用日志查询读取输出。

### 宿主机管理

VOS 系统管理员打开会话，点击「宿主机管理」，再点击「开启宿主机管理」。Agent 可列出宿主机 Docker 容器、查看近期日志，并按完整容器 ID 提议启动、停止、重启或删除。执行前请在会话里核对目标并确认。删除要求容器已停止，数据卷保留。点击「关闭宿主机管理」可提前结束。授权在 30 分钟后过期，每次调用都会核验管理员角色和 VOS 登录会话。接口见「设置 → API 文档」。

### 批量清理

让 Agent 把要删除的对象放进同一条清理提议。确认窗口随 VOS 界面语言切换，列出整批对象。点击一次「确认执行」或「跳过」。执行后会显示每个对象的删除结果。VOS 运维支持识别到的旧版 `created` 和 `exited` 容器。批量上限和错误处理见 API 文档。

## 框架与插件升级

运行时为 DSH 0.2.2-rc.3。升级后首次打开 v-harness 时会移除 DS Bot 插件及其设置入口，保留其历史数据。V-Scheduler 和添加个人模型的入口均在「设置 → 模型」。以上插件使用现有 Agent API 的会话和任务接口，插件面板的内部接口由对应插件管理。

插件携带旧存储模块时，租户进程统一使用当前安装的存储服务，保持工作区与会话服务的模块身份一致。会话文件和工作区归属保存在持久化用户目录。升级后历史未显示时，应先检查启动错误再处理会话文件。Agent API 路径和鉴权约定保持现状。

## 内置技能

在会话里输入技能名，例如 `/archify`，或直接描述任务。镜像包含技能及其运行依赖。

- **Archify** 生成可交互的独立 HTML 架构图。将源 JSON 与 HTML 保存在工作区，后续可以继续修改。
- **Mnemon** 在当前 VOS 用户的持久目录里跨会话保存和检索偏好、决策及项目事实。直接说要记住或忘记什么。它走本地 CLI，无需云端密钥。
- **PPT Design Skill** 生成原生可编辑的 PowerPoint 并用 LibreOffice 渲染预览。可使用本地配图、Image Studio 或用户配置的图片服务。
- **Vox Director** 用 ffmpeg 合成纸拼贴讲解视频。用 Atlas Cloud 生成素材时，由用户配置 `ATLASCLOUD_API_KEY`，消耗该账号额度。已有片段可在本地合成配音、音乐和字幕。
- **PGV** 可直连同一台 VOS 上的 PostgreSQL / pgvector（`pgv:5432`）、共享 Redis（`pgv-redis:6379`）和数据库连接器网关（`http://pgv-viewer:8081/app/com.ictrek.pgv`）。安装并启动 PGV，配置获准的服务凭据后，在会话中输入 `/pgv`，例如“检查我的 PostgreSQL 数据库安装了哪些扩展”。在 **设置 → 产品技能 → VOS 服务** 管理该技能。PostgreSQL 和 Redis 使用各自的凭据。连接器 HTTP 要求名为 `admin` 的 VOS 账号建立 PGV 会话，接口细节见 **PGV → 接入指南 → API 与协议参考**。如果 Agent 启动后才安装或重建 PGV，请重启租户运行实例以刷新内部地址。

Agent API 的鉴权和会话用法见「设置 → API 文档」。新技能沿用现有会话接口。

在「设置 → 模型」选择 V-Scheduler 提供的 ModelInfer DeepSeek V4 对话模型，再从新会话输入区的模型选择器选择思考级别。支持「关闭」「低」「高」「最高」，默认「高」。Chat Completions 的请求体分别通过 `reasoning_effort` 发送 `none`、`low`、`high`、`max`。可选级别随原有 Agent 会话模型目录返回。

## 算力节点与模型部署

打开「设置 → VOS 运维」，授权诊断后查看「机器」和「应用后端」。点击「在 V-Scheduler 管理算力节点」或「在 Image Studio 部署后端与准备模型」，可使用当前 VOS 身份进入对应应用。节点登记、硬件复验、容器验证、后端部署和模型准备需要对应服务的管理员权限。

也可以在会话中让智能体操作。例如「列出算力节点，在我选定的节点部署 Image Studio 后端，准备模型并报告传输和注册进度」。SSH 凭据通过私有 JSON 文件提供。智能体通过租户 socket 使用当前 VOS 身份。收到部署回执后继续查询状态。模型准备依次显示源文件检查、复制或共享存储、目标校验与注册，达到「registered」后再使用该部署生成。中断的准备流程可重试。删除远端模型前，由对应服务检查在途任务，随后注销该模型并删除它在目标节点上的文件。

## OpenMotion 与文件持久化

预装 **OpenMotion 0.2.1**，插件名称为 `openmotion-dsh`，使用官方本地应用的 MCP 工具和 Skills。默认开启，可直接在对话中请求创建 OpenMotion 项目、动画或导出视频。项目数据写入 `$HOME/workspace/OpenMotion`。媒体供应商需要单独配置，较大的渲染需要足够的 CPU、内存和磁盘。

使用步骤：

1. 在 v-harness 选择工作区，在「插件 → 已安装 → openmotion-dsh」确认开关开启；如有重启提示，按提示重启工作区。
2. 在对话里说「用 OpenMotion 打开模板库」或描述动画的主题、时长、画幅和风格。智能体调用插件后，点击它返回的预览/Studio 链接；仅打开插件详情页不会打开编辑器。预览链接仅供当前 VOS 账号访问；保留完整路径、参数和 # 片段，登录失效后刷新工作台再打开。 若回复只有纯文本路径，请让智能体返回可点击的 Markdown 链接，或从「服务」面板打开 OpenMotion。模板库与项目界面的资源和 API 均通过同一预览服务加载，刷新时保留原链接。
3. 在预览中检查画面和时间轴，在对话里提出修改；先预览，再确认导出。生成图片、视频、配乐或配音素材时，先按 OpenMotion 的引导配置相应供应商。
4. 确认后让智能体导出 MP4，把项目、素材和成片保存在工作区。项目目录为 `$HOME/workspace/OpenMotion`；从返回的文件链接下载或另行备份。

可直接复制：「用 OpenMotion 做一个 10 秒、16:9 的产品介绍动画，先用文字和几何图形，给我分镜和可打开的预览；等我确认后再导出 MP4，把项目和视频保存到工作区。」

租户主目录中的工作区、设计文件、导出文件、会话和插件设置通过 `${VOS_APP_STORAGE_PATH}/data:/data` 保存在主 VOS 机器上。交付文件请保存在 `$HOME/workspace`。普通容器重建和应用升级会沿用该存储。删除应用数据或修改存储设置前，请先备份应用存储。


## 默认开启的语音与实验功能

OpenMotion、Billion Context，以及「插件 → 已安装 → 实验性插件」中的语音输入、自定义插件索引、自动授权审查、变更请求与工作树均默认开启。ModSearch 保持默认关闭。

语音输入默认选择 **V-Voice · V-Scheduler**，复用 V-Voice 已启用的 ASR 模型，识别请求经过 V-Scheduler 的用户权限和资源调度；v-harness 发布镜像不包含本地 SenseVoice 插件及其 sherpa-onnx 原生依赖，不下载或装载本地识别模型。先安装并启动 V-Voice 与 V-Scheduler，在 V-Voice 准备 ASR 模型。然后在语音输入详情页允许麦克风、选择输入设备和识别语言，在会话输入区录音，结束后核对转写文字，再发送消息。服务未就绪时检查 V-Voice 模型和调度资源，再重试；登录过期时刷新 v-harness。升级会把原本地 SenseVoice 选择迁移至该服务，保留旧模型文件。

在「插件 → 已安装 → 语音输入」打开「识别服务 / 运算节点」下拉框。`V-Voice · V-Scheduler` 使用自动路由；带模型名和节点 ID 的 `V-Voice · <模型> · <节点>` 选项使用该节点已登记的部署和执行器。先由管理员在 V-Voice 准备后端与模型，点击「刷新运算节点」后再选择。选择按当前账号保存，录音开始时固定；节点失效或执行位置不匹配时本次识别失败，不切换到其他节点。刷新后重新选择可用项，再录音。节点功能要求配套版本通过 V-Scheduler 提供 `/api/v1/voice/compute/placements` 和 `/api/v1/voice/compute/transcriptions`；旧版只显示自动服务。

变更请求与工作树所需 Git、GitHub CLI (`gh`) 和 GitLab CLI (`glab`) 已随镜像安装。访问私有仓库仍需在当前租户中完成相应账号登录；开启自定义插件索引不会自动添加索引源。默认启用自动授权审查只使该访问模式可选，不会改变已有会话的访问模式。

语音转写使用已有 `speech/catalog`、`speech/configure`、`speech/prepare` 和 `speech/transcribe` Remote 协议，麦克风音频不会自动提交为 Agent 消息。公开会话 API v1 的路径、鉴权、请求和事件格式不变。
