# V-Office 云端文档

当前 VOS 用户在 V-Office 里有一份私有文档目录。本 skill 把产物推上去、把云端的取下来改，或给用户一条在线编辑直链。

所有命令都用同一个入口（绝对路径固定，不要 cd）：

```bash
node /opt/v-harness/skills/voffice/scripts/voffice.mjs <命令> [参数...]
```

每个命令输出一个 JSON 对象；失败时退出码非 0，错误在 stderr。

## 命令

| 命令 | 用途 |
|---|---|
| `me` | 确认当前令牌归属的用户，排障第一步 |
| `list [--links <n>]` | 列出「我的文档」全部文件；前 n 个（默认 10）附 `viewUrl` 只读预览直链 |
| `open <name> [--readonly] [--lang zh-CN] [--fresh]` | 取一条在线编辑（或只读预览）直链，即取即用 |
| `download <name> [--out <路径>]` | 下载到 workspace（默认 `./<name>`） |
| `view <name> [--out <路径>]` | 下载后立刻用 `present` 交付给用户查看 |
| `upload <文件> [--name <云端文件名>]` | 新建或原子覆盖云端文档 |
| `rename <name> <新名字>` | 重命名 |
| `delete <name>` | 删除 |
| `health` | 连通性检查 |

支持 docx / xlsx / pptx / pdf / odt / ods / odp / csv / txt / md，单文件上限 100 MB。同名上传是原子覆盖。

## 交互原则

- **每个动作的回复都是「回执 + 下一步的钩子」**：告诉用户发生了什么，并预告下一步能做什么。
- **链接是消耗品，不是资产**：编辑直链短时效（约 1 小时）、随取随新。用户说链接过期/打不开，直接重新 `open` 一条新的，不要排查旧链接、不要让用户重新登录。
- 直链自带编辑凭证，不要引导用户把链接贴到群聊等公开场合。

## 列文档（"看看有哪些文档 / 我云端有什么"）

1. `list`。
2. 排版成清单卡片：每行 = 文件名 + 修改时间 + 大小 + `[打开](viewUrl)`；按返回顺序（最近修改在前）展示。
3. `viewUrl` 是只读预览直链，直接把文件名或"打开"做成链接即可，用户点哪份看哪份。
4. 结尾留钩子："要编辑哪份跟我说名字；想改内容我也可以直接帮你改。"
5. 超过 10 个文件时，先列前 10 个，说明"还有 N 个，要看完整名单再说一声"（用 `list --links 0` 可拿纯列表）。

## 在线编辑（"打开 / 我要改 / 编辑一下"）

1. `open <name>`：返回 `url`（绝对地址，自带登录态）与 `expiresIn`。
2. 把 `url` 原样放进 markdown 链接：`[在线编辑《文件名》](url)`。
3. 交代三件事：**保存自动写回云端这份文档**；链接 `expiresIn` 内有效，过期我再给一条；多人打开同一份会进入同一个协同会话。
4. 预告闭环："改完（或改到一半想让我接着弄）回来说一声，我拉最新版继续。"

不要自己拼 `/editor` 或 `cool.html` 地址，也不要用 `present` 去开编辑器——`open` 返回的 `url` 是唯一入口。

## 在线只读预览（"给我看看 / 看一眼"）

- 优先用 `list` 返回的 `viewUrl`，或 `open <name> --readonly`：零下载、原格式渲染，比下载 + `present` 快。
- 需要下载后处理内容（改数据、抽取文字）才用 `download` / `view`。

## 编辑后重开（文档刚被覆盖又开着编辑器）

用户在编辑器里改着，agent 又 `upload` 覆盖了同名文档时，编辑器内存副本已过期：`open <name> --fresh` 取一条强制重读盘的新链接，并提醒用户旧编辑页不要再保存。

## 交付流程（用户要"存到 V-Office / 归档 / 发我一份"）

1. 在 workspace 里把文档准备好，文件名要能表达内容，带受支持扩展名。
2. `upload <文件> --name '<文件名>'`。
3. 回执说明已保存并给出文件名，附钩子："要我给一条在线编辑链接吗？"

## 改名流程

1. **歧义必确认**：用户说"那份报告"这类模糊指代时，先 `list` 找出匹配项（带修改时间帮用户回忆），列候选让用户选，绝不猜。
2. `rename <name> <新名字>`。
3. 回执展示 `旧名 → 新名`，并主动提醒：**编辑链接跟文件名走**——编辑器里还开着旧名字这份的话，重新点一次打开即可，内容不会丢。

## 删除流程

- 删除前必须得到用户明确确认；`delete` 不可恢复。删除不做成列表里的顺手操作，避免误触。

## 修改内容的完整闭环

1. 先 `view`/`download` 再改：用户说"改一下上次那份报告"，先下载，改完再 `upload` 覆盖。
2. 覆盖后提醒：如果用户正开着在线编辑，用 `open --fresh` 重新给一条链接。

## 规则

- 文件名不要带路径或 `..`；中文、空格由脚本负责编码，不要手动编码。
- 云端是扁平结构，没有目录、没有移动/复制、没有分享链接、没有历史版本，不要承诺这些。
- 失败就如实转述，不要静默重试：
  - `401` → VOS 登录令牌过期，让用户刷新 v-harness 页面后重试；
  - `404` → 当前用户目录下没有这个文件，先 `list` 确认名字；
  - `409` → 目标名已存在，或文档在别的窗口被改过，先与用户确认覆盖/改名；
  - `413` → 超过 100 MB；
  - `423` → 文档正被别的窗口在线编辑锁定，稍后再试；
  - `503`（warming_up）→ 在线编辑器正在启动，几秒后重试；`503`（unavailable）→ 当前部署没有在线编辑器，改用 download + present。

## 环境

脚本自己找接入点，不需要你拼地址或令牌：

1. `$HOME/.dsh/voffice.sock`（v-harness 网关按租户提供的本地能力端点，鉴权由网关完成）；
2. 本地调试时才用 `V_OFFICE_URL` + `V_OFFICE_BEARER_TOKEN`。

因此**不要**自己 `curl` v-office 的地址：模型侧拿不到令牌，直连只会 401。
