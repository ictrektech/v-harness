# 公司知识库

公司知识库由 WeKnora 提供，当前账号能看到的库由管理员分配。检索结果带稳定出处（`chunk_id` / `knowledge_id` / `knowledge_base_id` / `title` / `chunk_index`）：界面会把这一轮检索到的片段按**同样顺序**编号列在回答下方，你在正文里用 `[1]`、`[2]` 这样的编号指向它们。所以**不要改写或省略出处字段**。

所有命令都用同一个入口（绝对路径固定，不要 cd）：

```bash
node /opt/v-harness/skills/weknora/scripts/weknora.mjs <命令> [参数...]
```

每个命令输出一个 JSON 对象；失败时退出码非 0，错误在 stderr。

## 命令

| 命令 | 用途 |
|---|---|
| `kbs` | 列出当前账号能看的库（id、名称、类型、文档数） |
| `docs <库名或ID> [--keyword 词] [--limit 500]` | 列出这个库里的文档（id、标题、文件夹、解析状态） |
| `search <关键词> [--kb 库名,库名] [--doc 文档ID或库名/文档名] [--limit 8]` | 检索片段，带出处 |
| `read <knowledge_id>` | 读一篇文档的全部内容，按段落顺序 |
| `ask <问题> [--kb 库名,库名] [--doc 文档ID或库名/文档名]` | HybRAG 自己的 RAG 问答，答案和引用直接返回 |

五个命令都是成品：`docs` 和 `read` 内部自动翻页，不需要传页码。

## search 还是 ask

- 用户要**成段的回答**（"为什么""怎么做""介绍一下""有什么区别"）→ **第一个动作就是 `ask`**，不要先 search 铺垫。HybRAG 会自己写好答案。
- `ask` 返回了 `formatted_answer` → **你的回复正文 = formatted_answer 逐字复制，本轮到此结束**。它就是排好版的最终答案：引用已转 `[n]`、结构已排好。**禁止**改一个字——不改措辞、不换列表符号、不重排、不加开头结尾；**禁止**再跑任何工具验证。逐字复制完就停。
- `ask` 没有 `formatted_answer`（只有 instruction 说没答案）或报错 → 才允许退回 `search` 自己组织，几行就够。
- 用户要**零散的要点**（"有哪些""列一下""在哪"）→ 直接 `search`，按编号规则组织，几行就够。

## 消息里的范围标记

在输入框打 `@` 选库（还能继续选到具体文档），会往消息里插入标记，表示这一轮只看这些范围：

- `<knowledge-base>库名</knowledge-base>` —— 限定知识库
- `<knowledge-document>库名/文档名</knowledge-document>` —— 限定到具体文档

规则：

- **有标记，也提了问题**：把库名传给 `--kb`、文档名对应的 id 传给 `--doc`，不要顺带搜别的库。
- **有标记，但没提问题**：不要反问，直接在这个库里做一次概览检索（挑「制度」「流程」「模板」这类宽泛词），回答库里大致有什么，最后给一句可直接点的示例问法。
- **没有标记**：搜所有可见库。

## 有哪些库 / 哪些文档

用户问「有几个知识库」「有哪些库」「能查什么」时跑 `kbs`：一句话说数量，然后逐个列出库名。问「某个库里有什么」时跑 `docs <库>`：说篇数，再列 3–5 个代表性文档名。都不要把 JSON 贴出来。

库清单和文档清单没有卡片兜底：正文写不写全，用户就只能再问一次。

## 检索流程

1. 先判断范围：有标记按标记，没有就全库。
2. `search <核心词>`，不要直接把整句问题当查询词。
3. 回答时用 `[n]` 标出处，不要在正文里抄文档名和段号（写法见下一节）。
4. 检索不到就说「知识库里没有找到相关内容」，**不要用通用知识补全**。

## 答案怎么写

**编号 `[n]`**：指这一轮检索到的第 n 条片段，按它在 `search` 结果 `citations` 里的顺序数，从 1 开始；补搜过就按出现先后接着数。只能引用本轮 `search` 返回过的片段——`read` 读到、但检索结果里没有的内容不要编号，也不要自己造号。界面按同一份数据排序，号对不上，读者就点到了别处。

**版式**，默认按这个写：

- 第一句给结论。不要「根据知识库」「以下是」这类开场。
- 分点用无序列表，一条一句话：`- **关键词**：内容[n]。`
- 多值对比（天数、额度、审批档位）用表格。
- 编号放在标点前：`年假 5 天[1]。`；连着引两条写 `[1][3]`。
- 全文一般不超过 8 行；结尾最多一句补充或反问，不要「希望有帮助」这类客套。

**不要**在正文里写「《文档名》#3」——那是编号的活，原文由界面在回答下方展开；也不要贴 JSON 或整段原文。

检索不到时，直接说知识库里没有找到相关内容，再给一句能立刻试的建议（换个检索词，或用 `docs` 确认文档在库里）。

## 什么时候才 read

`search` 返回的片段通常已经够回答，**默认不要 read**。只有这两种情况才读全文：

- 用户**点名了某篇文档**（「《宪法.md》讲了什么」「第二章那个文档」），要按整篇讲；
- 搜索结果里同一篇文档被多次命中、片段互相矛盾或缺上下文，必须看全文才能判断。

除此之外，一律只用 `search` 的片段回答。**禁止**为了「更全面」先读整篇再挑内容——那是错的顺序，也浪费上下文。

## 失败处理

任何命令报错时，先跑一次 `kbs`，按它的结论如实转述，不要猜、不要重试：

| 现象 | 结论 | 该对用户说什么 |
|---|---|---|
| 脚本报「能力端点不存在」 | 当前会话没有完成 VOS 登录 | 请在 v-harness 页面重新登录后重试 |
| 脚本报 `EACCES`（连接 socket 被拒） | 能力端点属主还没交给当前账号（网关刚启动或交接失败） | 需要管理员重启网关；这是服务端权限问题，**不要请求或建议提高沙箱权限** |
| `kbs` 报「还没有被分配知识库」 | 有身份但没有库 | 当前账号还没有被分配知识库，请联系管理员 |
| `kbs` 正常但 `search` 为空 | 服务与权限正常，是检索没命中 | 换个检索词，或用 `docs` 确认文档在库里 |
| 报 `HTTP 401` | 登录令牌失效 | 登录已失效，请刷新页面重新登录 |
| 报 `HTTP 403` | 该库没有读权限 | 当前账号没有这个库的权限，请联系管理员 |

`--kb` 只接受 `kbs` 里列出的库，不要臆造。
