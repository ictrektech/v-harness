# 公司知识库

公司知识库由 WeKnora 提供，当前 VOS 用户能看到的库由管理员分配。检索结果带稳定出处（`chunk_id` / `knowledge_id` / `title` / `chunk_index`），界面会把它们渲染成引用角标，所以**不要改写或省略出处字段**。

所有命令都用同一个入口（绝对路径固定，不要 cd）：

```bash
node /opt/v-harness/skills/weknora/scripts/weknora.mjs <命令> [参数...]
```

每个命令输出一个 JSON 对象；失败时退出码非 0，错误在 stderr。

## 命令

| 命令 | 用途 |
|---|---|
| `health` | 检查服务、身份和可见知识库；排障第一步 |
| `search <关键词> [--kb 库ID,库ID] [--limit 5]` | 检索；不传 `--kb` 时搜索全部可见库 |
| `read <knowledge_id> [--limit 100]` | 读一篇文档的分段，按顺序；`truncated: true` 表示还有更多 |

## 打开知识库（`@hybrag` 或「有几个知识库」）

以下任一情形，都**直接跑 `health`**，用它的 `knowledge_bases` 回答：

- 消息里有 `<knowledge-base>hybrag</knowledge-base>`；
- 用户问「有几个知识库」「有哪些库」「能查什么」。

回答：一句话说数量，逐个列出库名。界面会把同一次 `health` 的结果渲染成知识库卡片，所以正文写短，不要把 JSON 贴出来。列完可以问「想查哪个库、查什么」，但**不要问「你想让我做什么」**。

## 检索流程

1. `search <用户问题的核心词>`，不要直接把整句话当查询词。
2. 结果里的 `snippet` 只能说明「命中了什么」。要引用具体条款、数字、步骤时，先 `read <knowledge_id>` 取原文，再回答。
3. 回答时把用到的出处一起给出：文档标题 + 分段序号。
4. 检索不到就说「知识库里没有找到相关内容」，**不要用通用知识补全**。

## 只有范围、没有问题

用户消息里只有 `<knowledge-base>某个库</knowledge-base>` 而没有具体问题时，**不要反问**。直接在该范围内做一次概览检索（挑一个宽泛词，比如「制度」「流程」「模板」），回答这个库里大致有什么，最后给一句可直接点的示例问法。

## 失败处理

任何命令报错时，先跑一次 `health`，按它的结论如实转述，不要猜、不要重试：

| health 输出 | 结论 | 该对用户说什么 |
|---|---|---|
| 脚本报「能力端点不存在」 | 当前会话没有完成 VOS 登录 | 请在 v-harness 页面重新登录后重试 |
| 脚本报 `EACCES`（连接 socket 被拒） | 能力端点属主还没交给当前账号（网关刚启动或交接失败） | 告诉用户需要管理员重启网关；这是服务端权限问题，**不要请求或建议提高沙箱权限** |
| `service.ok: false` | 知识库服务不可用 | 这台机器上的知识库服务没有响应，请联系管理员 |
| `identity: unauthenticated` | 服务在，但登录令牌失效 | 登录已失效，请刷新页面重新登录 |
| `identity: ok` 且库列表为空 | 有身份但没有任何库 | 当前账号还没有被分配知识库，请联系管理员 |
| `identity: ok` 且库列表非空 | 服务与权限正常 | 说明是查询本身没命中，换个检索词 |

`--kb` 只接受 `health` 里列出的库 ID，不要臆造。
