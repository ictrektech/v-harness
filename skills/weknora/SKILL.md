# 公司知识库

公司知识库由 WeKnora 提供，当前账号能看到的库由管理员分配。检索结果带稳定出处（`chunk_id` / `knowledge_id` / `title` / `chunk_index`），界面会把它们渲染成引用角标，所以**不要改写或省略出处字段**。

所有命令都用同一个入口（绝对路径固定，不要 cd）：

```bash
node /opt/v-harness/skills/weknora/scripts/weknora.mjs <命令> [参数...]
```

每个命令输出一个 JSON 对象；失败时退出码非 0，错误在 stderr。

## 命令

| 命令 | 用途 |
|---|---|
| `kbs` | 列出当前账号能看的库（id、名称、类型、文档数） |
| `docs <库名或ID> [--keyword 词] [--limit 500]` | 列出这个库里的文档（id、标题、文件夹、解析状态） |
| `search <关键词> [--kb 库名,库名] [--doc 文档ID或库名/文档名] [--limit 8]` | 检索片段，带出处 |
| `read <knowledge_id>` | 读一篇文档的全部内容，按段落顺序 |

四个命令都是成品：`docs` 和 `read` 内部自动翻页，不需要传页码。

## 消息里的范围标记

`@` 选库、证据面板的「用这 N 个库提问」，都会往消息里插入标记，表示这一轮只看这些范围：

- `<knowledge-base>库名</knowledge-base>` —— 限定知识库
- `<knowledge-document>库名/文档名</knowledge-document>` —— 限定到具体文档

规则：

- **有标记，也提了问题**：把库名传给 `--kb`、文档名对应的 id 传给 `--doc`，不要顺带搜别的库。
- **有标记，但没提问题**：不要反问，直接在这个库里做一次概览检索（挑「制度」「流程」「模板」这类宽泛词），回答库里大致有什么，最后给一句可直接点的示例问法。
- **没有标记**：搜所有可见库。

界面里单独的「浏览知识库…」只是浏览，不产生消息，不需要你回答。

## 有哪些库 / 哪些文档

用户问「有几个知识库」「有哪些库」「能查什么」时跑 `kbs`，一句话说数量，逐个列出库名。问「某个库里有什么」时跑 `docs <库>`，说篇数和几个代表性文档，不要把 JSON 贴出来。

界面会把同一次 `kbs` 的结果渲染成卡片，所以正文写短。

## 检索流程

1. 先判断范围：有标记按标记，没有就全库。
2. `search <核心词>`，不要直接把整句问题当查询词。
3. 回答时把用到的出处一起给出：文档标题 + 分段序号。
4. 检索不到就说「知识库里没有找到相关内容」，**不要用通用知识补全**。

## 什么时候才 read

`search` 返回的片段通常已经够回答，**默认不要 read**。只有这两种情况才读全文：

- 用户**点名了某篇文档**（「《宪法.md》讲了什么」「第二章那个文档」），要按整篇讲；
- 搜索结果里同一篇文档被多次命中、片段互相矛盾或缺上下文，必须看全文才能判断。

除此之外，一律只用 `search` 的片段回答。**禁止**为了「更全面」先读整篇再挑内容——那是错的顺序，也浪费上下文。

## 失败处理

任何命令报错时，先跑一次 `kbs`，按它的结论如实转述，不要猜、不要重试：

| 现象 | 结论 | 该对用户说什么 |
|---|---|---|
| 脚本报「能力端点不存在」 | 当前会话没有完成 VOS 登录 | 请在 v-harness 页面重新登录后重试 |
| 脚本报 `EACCES`（连接 socket 被拒） | 能力端点属主还没交给当前账号（网关刚启动或交接失败） | 需要管理员重启网关；这是服务端权限问题，**不要请求或建议提高沙箱权限** |
| `kbs` 报「还没有被分配知识库」 | 有身份但没有库 | 当前账号还没有被分配知识库，请联系管理员 |
| `kbs` 正常但 `search` 为空 | 服务与权限正常，是检索没命中 | 换个检索词，或用 `docs` 确认文档在库里 |
| 报 `HTTP 401` | 登录令牌失效 | 登录已失效，请刷新页面重新登录 |
| 报 `HTTP 403` | 该库没有读权限 | 当前账号没有这个库的权限，请联系管理员 |

`--kb` 只接受 `kbs` 里列出的库，不要臆造。
