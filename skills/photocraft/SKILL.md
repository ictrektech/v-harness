# PhotoCraft

PhotoCraft 是一个跑在 harness 旁边的完整图像编辑器。你通过 `photocraft_*` 工具驱动它，每一次编辑都是真实文档——有图层、有选区、有历史，不是一个一次性滤镜。

## 一、主路径：photocraft_edit，一张卡一步到位

`photocraft_edit` 是主入口。**你的工作是听懂用户想要什么像素结果，选一张卡（`intent`），把用户给的位置（框/笔迹）和参数传进去**，一次调用拿到成品图。不要用正则去猜用户的句子，理解语言是你的活。

| intent | 干什么 | 必备输入 |
|---|---|---|
| `film` | 整图调色风格（冷调/暖调/胶片）；带 `regions` 则为局部调色（羽化蒙版） | 什么都不用，`look`/`strength` 可选 |
| `cutout` | 把主体抠出、换底色 | 最好有框或笔迹；没有就按最显著主体抠 |
| `remove` | 让某块东西消失：水印、路人、字迹、魔术橡皮擦 | 框或笔迹标出位置 |
| `enhance` | 降噪、锐化、修画质 | 无；用户抱怨偏色时给 `autoColor: true` |
| `poster` | 海报排版 | `text` 必填 |
| `composite` | 把用户给的另一张图贴进来（换背景/天空） | `assets` |
| `brush` | 画笔涂画 / 橡皮擦 | `strokes` 笔迹；`color`/`erase` 可选 |
| `retouch` | 修图笔刷：`tool` 选 dodge 加深 / burn 减淡 / sponge 海绵 / blur 涂糊 / sharpen 锐化 / smudge 涂抹 / clone 仿制图章 / spotHeal 污点修复 / heal 修复画笔 / patch 修补 | `tool` + `strokes` |
| `fill` | 填充：`tool` 选 bucket 油漆桶 / gradient 渐变 | `tool` + 落点或起止点 + `color` |
| `transform` | 几何：`action` 选 crop / rotate / flipH / flipV / trim / resize | `action` + 对应参数 |
| `gray` | 转黑白 | 无 |
| `text` | 加一段文字，**位置由引擎决定（常见左下），不能指定** | `text` 必填；要精确位置改走 `type.create`（见第三节第 8 条） |

一句话判断：**能一句话说清的选一张卡；需要"只改这一块/分几步来/卡片外的活"才走第八节的 search + run。**

## 局部调色（复合语义，两次调用）

用户说"把花变冷调，其余变暖调"这类**分区域不同调**的活，这样拆：

1. **先整图**：`photocraft_edit { intent: "film", look: "warm" }`（"剩下的"那个调子）
2. **再局部**：`photocraft_edit { intent: "film", look: "cool", ...选区 }`——调整层的蒙版只落在选区里

选区怎么给，按用户的话里**有什么信息**选，不要硬凑坐标：

| 用户的话 | 传什么 | 示例 |
|---|---|---|
| 颜色可分（"那朵红花""金色的麦田"） | `color: "#rrggbb"`（你从图里取花的颜色） | 按颜色选，不需要坐标 |
| 位置可指（"那朵花""她的脸"） | `strokes: [{ points: [[x, y]] }]`，点在目标中间 | 选区按颜色自己长到边缘 |
| 大片区域（"上半部分""左边背景"） | `regions: [{ x, y, w, h }]` 粗框即可 | 3% 羽化自然过渡 |
| 用户亲手画的框/笔迹 | 原样传，**坐标绝不要改** | 这是最准的，优先级最高 |

3. **看预览图验收**：色块落错位置或长过头，挪点/换颜色重跑一次

## 二、参数量纲（按引擎声明，不要发明；用户没给数值就取轻档，见第三节「用户没说参数 = 自然微调」）

- `strength`（film）：1..100，默认 50。25 轻、75 明显、100 满量程。冷调朝青蓝、暖调朝红黄、bleach 提黑位降饱和
- `vignette`（film）：0..100，默认 30；`grain` 0..100，默认 0
- `shift`（cutout/composite）：-100..100，默认 -25，负值收边。主体边缘带一圈原背景时调到 -30 重跑
- `soften`（cutout）：0..100，默认 20
- `size`（brush/retouch）：笔刷直径 px。用户没说就别传，默认笔迹自己的宽度
- `opacity`（brush/fill）：1..100，用户没说就别传
- `strength`（retouch）：1..100，默认 50——加深减淡是曝光量、海绵是流量、模糊锐化涂抹是强度
- `margin`（remove）：0..0.1，默认 0.01，向外扩的余量
- `denoise` 0..10 默认 4；`sharpen` 1..500 默认 50
- 颜色一律 `#rrggbb`，由你把用户说的颜色（"红色""天蓝"）翻译成色值

## 三、纪律：改完必须看图

1. **动手前，先决定要不要侦察**：
   - 用户画了框/笔迹 → 坐标已在 `<region>` / `<strokes>` 里，**直接用，不要再估**
   - 整图类改动（调色 / 翻转 / 黑白 / 画质）→ 没有目标坐标，直接改
   - **文字点名的小目标**（"眼睛大一点""把这颗痣去掉"）→ 先 `photocraft_look` **侦察一次**：
     - 不知道目标大概在哪 → **先不传 `region`**，只看整图定位
     - 知道大概位置 → 传 `region`（0..1）换局部放大图：**黄框是你给的区域**、红十字是区域中心、主网格 + 框内细网格是标尺、左下青线 = 10px
     - 目标比网格还小就把 `grid` 调细（5 或 10）
     - **网格只用来定位和看边缘，量尺寸用数值行那个像素框**；量到的坐标换成 0..1 比例再动手
   - **侦察一次，坐标复用**：同一张图上接着改眼睛、嘴唇，坐标量一次就够，后面直接沿用 —— 慢从来不是"多看一眼"，是"估错坐标反复猜"
   - 命令不熟就 `photocraft_describe` 看参数（`blocked` 会写明现在为什么跑不了）；想确认当前文档状态用 `photocraft_inspect`
2. **动手时**：一个工作流一次调用。走卡片就一个 `photocraft_edit`；走 search + run 就把 `doc_open`、命令、`doc_export` 写进同一个 `photocraft_run { steps: [...] }`（会话会过期，拆开调用等于把历史丢掉，见第八节）
3. **动手后**：返回**两张图 + 一行数值**——整图缩略（看全局）+ 改动局部放大（看细节，十字与网格是标尺，看边缘有没有残边/黑圈/断裂）+ `画布 547×365；局部窗口 240,120 160×160px`。按改动类型决定看哪张：

   | 改动类型 | 主看 | 别漏 |
   |---|---|---|
   | 点/局部（眼睛、局部调色、模糊） | 局部放大图 | 整图扫一眼，确认没伤到别处 |
   | 蒙版/删除 | 局部放大图的边缘 | 整图看有没有残留（以前擦猫爪，局部干净、左下角还留着） |
   | 全局（调色、翻转、整图擦除） | **必须整图** | 只盯局部会漏色偏、接缝、被推到画布外的文字 |
   | 批量 | 一张对比表/contact sheet | 单张细节 |

   `preview` 参数控制返回哪张：`both`（默认，整图+局部）、`full`（只整图，整图类改动用）、`focus`（只局部，连续微调同一块最省）、`off`（只看数值，**仅限数值可判定的改动**；删除/抠图/合成必须看图）。
   数值行给的是 `画布 547×365；目标 180,117 65×44px；局部窗口 …`——「目标」就是你的框/笔迹在成片上的实际像素框，量尺寸、核对位置都用它。
   以下情况要重跑：
   - 抠图边缘有原背景残边 → `shift` 调到 -30 重跑一次
   - 填充区域糊/有鬼影 → 缩小框或换一张 nearby 采样，重跑一次
   - 调色太重/太轻 → `strength` 减半或加倍，重跑一次
   - **交付线**：到线就交，不到线最多补 1 次，然后如实说明哪里不到位——不要"差不多就交"，也不要"不满意就一直磨"

    | 操作 | 交付线 | 最多 |
    |---|---|---|
    | 调色 / 风格 | 整图方向对，无明显断色 | 1 次 |
    | 小目标（眼睛 / 局部） | 局部无黑圈、无接缝，尺寸与目标差 ≤5% | 2 次 |
    | 删除 / 抠图 | 边缘无残边，纹理连续 | 2 次 |
    | 文字 / 排版 | 不压主体，不超出画布 | 2 次 |
   - **整图与局部各看一段**：整图（768 长边）看全局——色偏、接缝、遮挡；局部放大（512 长边，红字十字是窗口中心）看位置与边缘。颗粒、噪点两级都不完全可靠，按用户语义**一次定稿**，不要"看着觉得重了"就反复微调
   - **重跑不许在成品上叠加**：回到该改动之前的版本再跑，不要在已调色的 png 上继续叠，否则叠出双层颗粒/双重调色，越改越糟
### 参数试探的规矩

- **先定目标再动手**：开修前明确要什么效果、到什么程度（幅度、风格、边界在哪）。有参考就以参考为准；没有参考时按"自然、不夸张"作为默认预期
- **用户没说参数 = 自然微调**：没给数值时取该参数的轻档（量程的下三分之一，或引擎默认值）。宁可轻了等用户要"再强一点"，也不要一次做猛；用户明确要"明显""夸张"时才往量程上半段走
- **先验证机制，再调力度**：对没把握的命令，先用极限参数做一次小范围试验，确认它确实会改变画面；机制不成立时调参数是无效功
- **一次只验证一个变量**：先确认"有没有效果"，再调"力度大不大"。同时动多个参数，出问题就分不清是哪一个
- **同一处两次不对就停**：第二次仍不对，先区分"没生效"还是"参数不对"（用极限值试探来分辨），不要在原结果上继续叠加
- **做完一步立刻看图**：每完成一步就确认，不攒到最后统一看；早发现是改一处，晚了是整段返工
- **先找现成工具，不自己造**：需要放大、对比、量尺寸时，先用工具已经给出的能力；确认环境里确实没有现成方案再另想办法，不要一上来就手写底层实现

4. **交付**：`photocraft_edit` 自动出两个文件：`wish-<时间戳>.png`（可看可发）和 `.psd`（图层保留可再调）。交付时报两个名字。写文件名就好，不要输出 HTML 标签。要在回复里**直接展示成品**，就写 `![说明](wish-<时间戳>.png)`——必须用工作区里的成品名；工具结果里那两张附件叫 `*-preview.png` 和 `*-closeup.png`，**都只是附件，工作区没有这两个文件**，拿它们当图片地址会显示"图片无法预览"
5. **多轮修图**：用上一轮导出的 `wish-*.png` 继续改，`source` 直接写文件名（如 `wish-123.png`），工具会自己定位并上传；**省略 `source` 就是接着改最近一次交付的成品**
   - `.psd` 保图层但体积大，只用于存档（交给 Photoshop 二次编辑），**不要当 `source`**：`wish-*.png` 已经烘焙了前面所有改动，接力用它效果一样
6. **返工回哪一版**：回到**出问题那一步之前**的 `wish-*.png` 重做，不要在原图上重来（丢掉前面正确步骤），也不要在最终成品上继续叠（双层字、双重调色）。工作区里的 `wish-*.png` 按时间戳排序，越新越靠后
7. **建对象和改属性是两条命令**：多数族把「建」和「设」拆开——`type.create` 只建文字图层，上色加粗要 `type.setStyle`；`layer` / `shape` / `path` 也是同样的拆法。看到 `*.create` 就顺手查 `*.setStyle` / `*.set` / `*.apply`，给的字段超出声明会被直接拒绝（引擎不会静默忽略）。两步要连续做就写进**同一个** `photocraft_run { steps }`
8. **文字要精确落位，别用 `text` 卡片**：`photocraft_edit` 的 `text` 意图只在图上加一段字，**位置由引擎决定（常见是左下角），不能指定**。看着预览不对时，改走 `type.create`，用 `x` / `y` 或 `box` 给目标位置
   - **两套坐标系别混**：卡片层的 `regions` / `strokes` / `fill` 落点是 **0..1 相对比例**（工具内部乘画布尺寸）；`photocraft_run` 里的引擎命令（`type.create`、`select.*`、`layer.*`…）要 **像素**，先用 `photocraft_inspect` 拿画布尺寸自己乘
   - 例：547×365 的画布，文字落在水平居中、距顶 10% → 卡片传 `{ x: 0.5, y: 0.1 }`，命令传 `{ x: 273, y: 36 }`；把 `0.5` 直接交给命令，字会挤在左上角贴边，看着像没加进去
9. **几何变换会连文字一起翻**：`transform`（rotate / flipH / flipV）作用于整张图，包括已经加好的文字图层——先翻转再加字，否则字会跟着倒过来或跑到另一侧。已经翻了就把标题重新摆一次，别指望自动纠正
10. **一句话多个需求**：先在心里列成清单（如"擦桶 / 调色 / 加字"），**逐个执行、每个做完就往下走**，不要在第一个需求上反复打磨把后面的拖没；全部做完再统一交付

## 四、图从哪来

消息里的 `<region>` 标签把同一张图写两遍，用 `img`，忽略 `image`：

- `img="1"` 是消息里第一张图，`img="2"` 是第二张——就是附件顺序
- `image="att_7f3c"` 是编辑器草稿 id，**永远匹配不上任何东西**，不要解析它

图片标识形如 `sha256:<hex>`，把 id **原样**作为 `source` 传入（素材则进 `assets`）。绝对路径也认。**不要把图先拷进工作区**，这一步只会制造失败。只支持图片格式，上限 30MB。

## 五、用户画的框和笔迹

用户在图上拖拽时，每个框会有一个标签：

```text
把这块的背景换成第二张
<region role="cut" n="1" img="1" image="att_7f3c" x="0.1410" y="0.6900" w="0.7100" h="0.1100"/>
```

- 比例已经是 `0..1`，**绝不要重新换算**；`role="cut"` 红框按 `n` 顺序进 `regions`
- **框不会画进图片里**：你收到的永远是原图，红框只以这行标签的坐标存在。**不要在图里找红框**，也别因为"图上看着干净"就认为用户没画——有标签就是画了，按坐标算
- 用户涂的笔迹是 `<strokes>` 标签，**tag 体就是点数组**：`<strokes img="1" n="1">[[0.31,0.52],[0.33,0.51]]</strokes>` → `strokes: [{ points: [[0.31, 0.52], [0.33, 0.51]] }]`；`n=1` 第一笔建立选区，后面的笔依次追加
- 笔迹比框精确：擦除、画笔、修图笔刷、局部调色优先用笔迹
- **绝不凭空造框，也不要"为了保险"把框放大**：用户是在他看着的图上量的

## 六、两张图

用户附了两张：**第一张是主体，第二张是素材**。"换成这张背景/天空"→ 素材进 `assets[0]`。红框 + 素材 = 素材填进框里（按序号配对）。没有红框 = 素材贴到主体后面。"做张海报"的文案放 `text`，没有文案先问一句。

## 七、超出一句话的活

局部选区、按颜色选、蒙版、路径、滤镜库、动作、批处理——卡片装不下的活走这条链：

1. `photocraft_search { query: "按颜色选区域" }` 用自然语言搜（中英文都认），返回 id、参数、菜单路径
2. `photocraft_describe { id }` 看参数与前置：`blocked` 写的就是"现在为什么跑不了"，先按它把条件凑齐再动手
3. `photocraft_run` 执行；`steps` 里把 `doc_open`、命令、`doc_export` 一次跑完（导出后若 steps 里给过坐标，会附一张目标区域的放大裁切；`preview: "off"` 可关），参数按 describe 的声明给，传错字段会被拒绝。`doc_export` / `doc_save` 的 `path` 写**工作区落点**（如 `out/最终.png`），省略就自动命名 `wish-<时间戳>.png`——两种都会下载回工作区，导出后直接读文件或 `present` 即可

## 八、会话工具与文档生命周期

`photocraft_run` 的 id 分两族：**会话工具**管文档本身，**绘图命令**改像素。两族都可以写在同一个 `steps` 里，按顺序执行。

| 会话工具 | 参数 | 作用 |
|---|---|---|
| `doc_open` | `{ path }` | 打开一份文档。`path` 是**工作区文件名**（如 `wish-123.png`）或附件 id `sha256:<hex>`，**不是任意本地绝对路径**——引擎只打开它自己有权访问的位置 |
| `doc_new` | `{ width, height }` | 新建空白文档 |
| `doc_inspect` | `{}` | 读当前文档状态（尺寸、图层、选区、历史） |
| `doc_save` | `{ path, format }` | 存盘。`path` 是**工作区里的落点**（相对路径，可含子目录如 `out/最终.png`），不是引擎卷内的路径；省略时自动命名 `wish-<时间戳>.png` |
| `doc_export` | `{ path, format }` | 导出成品，同上。导出后文件**就在工作区**，可以直接 `present` 或 `![说明](out/最终.png)` |
| `doc_close` | `{}` | 关掉文档 |

**会话会过期**：引擎把会话和文档都放在内存里，空闲超时或服务重启后旧会话作废。客户端会自动重连并重新打开最近一次 `doc_open` 的文档，但**之前的编辑历史回不来**。所以：

- 一个工作流写成**一次** `photocraft_run { steps: [...] }`——`doc_open`、绘图命令、`doc_export` 一次跑完，不要拆成"先 open、再 run、再 export"
- 必须跨调用时，用上一轮导出的 `wish-*.png` 重新 `doc_open`，不要指望上个会话还活着
- 报 `no open document`、或发现文档状态不是刚才那样，就是会话换过了：重新 `doc_open` 再继续，别在错的状态上接着改

## 九、常见问题速查

| 症状 | 原因 | 处理 |
|---|---|---|
| `unknown command` | id 写错，或这一版没有 | `photocraft_search` 重找，别改拼写硬试 |
| `no open document` | 会话被换过，文档没了 | 重新 `doc_open`，整段工作流重跑 |
| `HTTP 404 / Not Found` | 会话失效 | 客户端已自动重连并重开文档，重试一次即可 |
| `blocked` | 前置条件没满足 | 读 `disabled_reason`，先做选择 / 建图层 / 开文档 |
| 找不到图片 X | 文件名不对 | 报错会列工作区最近 5 张图，换对的 `source` |
| 画面没变化 | 参数名给了但没生效 | `photocraft_describe` 核对字段名，别猜 |

## 十、最小工作流

```
1) 探   有框/笔迹直接用；文字点名小目标先 `photocraft_look` 侦察一次；整图类改动跳过这步
2) 查   不熟的命令：photocraft_search → photocraft_describe（看 blocked）
3) 干   一句话能说清 → photocraft_edit 一张卡；否则 photocraft_run { steps } 一次跑完
4) 验   看返回的整图与局部裁切（run 有坐标时也带局部图）；不合格按第三节的上限重跑一次
5) 交   报 wish-<时间戳>.png / .psd，需要展示就 ![说明](wish-<时间戳>.png)
```

## 十一、真实边界

- **没有生成式能力**：换脸、扩图、凭空画元素，交给 Image Studio
- **处理永远用原始字节**：不要让引擎先降采样
- **两级预览各管一段**：整图（`previewSide`，默认 768 长边）只看全局——色偏、接缝、遮挡、有没有伤到别处；局部放大（512 长边，网格 24px 一格、十字是窗口中心）只看位置与边缘——残边、黑圈、纹理断裂。颗粒、噪点这类细微差别两级都不完全可靠，按用户语义一次定稿，不要反复微调
- **`preview: off` 只适合纯数值可判定的改动**（调色强度、裁剪尺寸、导出规格）；删除、抠图、合成这类要看“有没有残留”的，只看数值就交付等于没验收
- **引擎的中间文件在 `photocraft-tmp/`**，成品才落工作区，别让用户去那里找
- `这个账号还没有被授予任何目录` → VOS 数据授权没配，不是程序坏了
